# 01 项目概述与架构

> 以问题为导向，帮助你快速理解「智能学习伴侣系统」的整体面貌。

---

## Q1：这个项目要解决什么问题？

**A：** 大语言模型（LLM）虽然强大，但存在两个核心痛点：

1. **幻觉问题** —— LLM 会编造不存在的知识，给出看似合理但实际错误的回答。
2. **缺乏个性化** —— LLM 无法针对「你正在学什么、你哪里薄弱」进行适应性教学。

本项目的目标是：用 RAG（检索增强生成）技术，让 LLM 的回答**基于用户自己上传的学习资料**，从而消除幻觉；同时加入知识追踪、苏格拉底对话、自动测验等机制，让系统**根据你的学习状态做个性化辅导**。

---

## Q2：项目的核心功能有哪些？

**A：** 五大功能模块：

| 功能 | 一句话描述 |
|------|-----------|
| **智能问答** | 上传资料后提问，系统从你的资料中检索相关内容，生成带引用的回答 |
| **文档管理** | 上传 PDF/Word/Markdown，系统自动解析、分块、向量化 |
| **测验练习** | 根据你的资料自动生成题目，追踪答题情况，识别薄弱知识点 |
| **知识图谱** | 从文档中抽取概念和关系，生成可交互的知识网络图 |
| **苏格拉底对话** | 不直接给答案，而是用引导式提问帮你自己思考出答案 |

---

## Q3：项目的技术栈是什么？各部分为什么选择这个技术？

**A：**

| 层次 | 技术选型 | 选型理由 |
|------|---------|---------|
| **前端** | Streamlit | Python 生态最快搭建交互式 Web 应用的框架，适合数据/AI 类项目 |
| **大语言模型** | Google Gemini（可配置多家） | 性价比高、支持中文、有免费额度 |
| **向量嵌入** | Gemini Embedding | 与 LLM 同生态，减少额外依赖 |
| **向量数据库** | ChromaDB | 轻量级、纯 Python、本地运行、无需外部服务 |
| **RAG 框架** | LangChain + LlamaIndex | LangChain 做链式编排，LlamaIndex 做文档解析 |
| **关系数据库** | SQLite | 零配置、单文件、适合单用户/小规模场景 |
| **文档解析** | PyPDF / python-docx / LlamaParse | 覆盖主流文档格式 |
| **重排序** | BGE-Reranker（硅基流动 API） | 提升检索精度的关键环节 |

## Q4：项目的整体架构是怎样的？

**A：** 项目采用**前后端分层但同进程运行**的架构：

```
┌─────────────────────────────────────────────────────┐
│                    用户浏览器                         │
└──────────────────────┬──────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────┐
│              Streamlit 前端（app/）                   │
│  主页 ── 智能问答 ── 文档管理 ── 测验 ── 图谱 ── 设置  │
└──────────────────────┬──────────────────────────────┘
                       │ 直接 Python 调用
┌──────────────────────▼──────────────────────────────┐
│              后端逻辑层（backend/）                    │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────────────┐│
│  │文档处理 │ │检索系统 │ │RAG链   │ │学习功能        ││
│  │parser  │ │vector  │ │chain   │ │quiz/socratic/  ││
│  │chunker │ │hybrid  │ │prompts │ │knowledge/kg    ││
│  │embedder│ │reranker│ │memory  │ │                ││
│  └────────┘ └────────┘ └────────┘ └────────────────┘│
│  ┌────────┐ ┌────────┐ ┌────────────────────────────┐│
│  │认证    │ │LLM路由 │ │配置管理                     ││
│  │auth    │ │router  │ │config                      ││
│  └────────┘ └────────┘ └────────────────────────────┘│
└──────────────────────┬──────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────┐
│                   数据层（data/）                     │
│  SQLite（用户/文档/对话/测验） + ChromaDB（向量索引）    │
└─────────────────────────────────────────────────────┘
```

**关键设计决策**：前端和后端运行在同一个 Python 进程中，前端通过 Python 函数调用直接使用后端模块，没有 HTTP API 层。这是因为 Streamlit 本身就是 Python 运行时，且项目是单用户/少用户场景，无需微服务化。

## Q6：数据在系统中是如何流动的？

**A：** 以一次完整的「上传文档→提问→获得回答」为例：

```
1. 上传阶段
   用户上传 PDF
       → DocumentParser 解析出纯文本
       → SmartChunker 切成父块（大）和子块（小）
       → DocumentEmbedder 把每个块转为向量
       → 向量存入 ChromaDB，块信息存入 SQLite

2. 提问阶段
   用户输入问题
       → 问题转为向量（query embedding）
       → HybridRetriever 同时做向量检索和关键词检索
       → RRF 算法融合两路结果
       → AdaptiveReranker 用重排模型精筛
       → 取出匹配子块对应的父块（更完整的上下文）
       → 将上下文 + 问题 + 对话历史组装成 Prompt
       → 通过 ModelRouter 发送给 LLM
       → LLM 返回带引用标注的回答
       → 回答和引用展示给用户，对话存入数据库
```

## Q7：项目中有哪些关键的设计思想？

**A：**

### 1. 父子块分离（Parent-Child Chunking）
- **子块**用于检索（小而精准）
- **父块**用于生成（大而完整）
- 好处：检索精度和上下文完整性兼得

### 2. 混合检索 + 自适应重排
- 向量检索擅长语义匹配，BM25 擅长关键词匹配
- RRF 融合两路结果，取长补短
- 重排器只在「不确定」时才启动，节省 API 调用

### 3. 多模型路由
- 不同功能模块可以配置不同的 LLM
- 比如问答用高质量模型，知识图谱用便宜模型
- 用户可在设置页自由切换

### 4. 知识追踪驱动个性化
- 记录每个知识点的答题正确率
- 自动识别薄弱点并推荐复习
- 测验出题时加权采样薄弱知识点

### 5. 苏格拉底式教学
- 不直接给答案，通过一系列引导问题让用户自己推导
- 分阶段：探索→澄清→深入→综合

## Q8：这个项目和普通的 ChatGPT 对话有什么本质区别？

**A：** 三个本质区别：

| 维度 | 普通 ChatGPT | 本项目 |
|------|-------------|--------|
| **知识来源** | 模型训练数据（可能过时/不准） | 用户自己上传的学习资料（可靠、可控） |
| **回答可信度** | 无法验证来源 | 每个回答标注出处（哪份文档、哪一页） |
| **学习适应性** | 对所有人一样 | 追踪你的知识掌握情况，针对薄弱点强化 |

## Q9：项目的用户使用流程是什么样的？

**A：**

```
首次使用
  注册账号 → 上传学习资料 → 等待系统处理

日常学习
  ├─ 智能问答：对着资料提问，获得有据可查的回答
  ├─ 测验练习：系统自动出题，做完后看薄弱点分析
  ├─ 苏格拉底对话：选一个话题，系统引导你深入思考
  └─ 知识图谱：可视化查看知识结构和概念关系

复习巩固
  └─ 查看错题本 → 系统针对错题生成追问 → 重做薄弱知识点
```

## Q10：项目有哪些外部依赖/服务？

**A：**

| 外部服务 | 用途 | 是否必需 |
|---------|------|---------|
| **Google Gemini API** | LLM 生成 + 文本嵌入 | 必需（至少需要一个 LLM） |
| **硅基流动 API** | BGE-Reranker 重排序 | 可选（提升检索质量） |
| **LlamaParse API** | 高质量 PDF 解析 | 可选（有本地 PyPDF 兜底） |
| **Antigravity API** | 备用 LLM 通道 | 可选 |

除此之外，所有组件（SQLite、ChromaDB、Streamlit）都在本地运行，无需额外部署数据库或服务器。
