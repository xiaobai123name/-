# 07 学习功能模块

> 理解测验生成、知识追踪、苏格拉底对话三大学习功能的设计逻辑。

---

## Q1：学习功能模块包含哪些子模块？它们之间的关系是什么？

**A：** 三个核心子模块，形成一个**学习闭环**：

```
测验生成（QuizGenerator）
    │  生成题目，用户作答
    ▼
知识追踪（KnowledgeTracker）
    │  记录对错，计算掌握率，识别薄弱点
    ▼
个性化出题
    │  薄弱知识点加权采样，针对性复习
    ▼
测验生成（回到起点，但题目更有针对性）
```

另外还有一个独立的子模块：
- **苏格拉底引擎（SocraticEngine）**：用引导式提问帮助深入理解

---

## Q2：测验是如何生成的？

**A：** 测验生成的核心思路是**从文档内容出发，让 LLM 生成题目**。

### 生成流程
```
1. 确定出题范围
   ├─ 综合复习：从用户所有文档中选取内容
   └─ 专项突破：从指定知识点相关的文档中选取

2. 检索文本块
   └─ 用 HybridRetriever 获取相关文本块

3. LLM 生成题目
   └─ 将文本块作为上下文，让 LLM 出题
       - 题型：单选题 / 多选题
       - 每题包含：题目、选项、正确答案、解析、关联知识点

4. 结构化输出
   └─ LLM 返回 JSON 格式的题目列表
```

### 为什么用 LLM 出题而不是题库？
- 题库需要人工维护，成本高
- LLM 可以根据**任意用户上传的资料**出题，不限定领域
- 每次出的题可以不同，避免重复

---

## Q3：测验有哪些出题策略？

**A：** 两种策略，解决不同的学习需求：

### 综合复习
- 从用户的所有文档中随机选取内容
- 覆盖面广，适合初次学习或全面复习
- 题目分布较均匀

### 专项突破
- 由知识追踪模块提供薄弱知识点列表
- 只从薄弱知识点相关的文档内容中出题
- 适合针对性复习，补足短板

两种策略的切换由用户在前端选择。

---

## Q4：知识追踪的核心算法是什么？

**A：** 采用**基于答题统计的简单追踪模型**：

### 核心公式
```
掌握率 = 答对次数 / 总答题次数
```

### 薄弱点判定规则
一个知识点被标记为「薄弱」需要**同时满足**两个条件：
- 掌握率 < 60%
- 总答题次数 ≥ 3

**为什么要两个条件？**
- 只用掌握率：可能第一次答错就标记为薄弱（100% → 0%），太敏感
- 只用答题次数：无法反映掌握程度
- 两个条件结合：至少答 3 次才下结论，减少偶然误判

---

## Q5：薄弱知识点是如何影响出题的？

**A：** 通过**加权采样**机制：

### 采样权重计算
```
权重 ∝ (1 - 掌握率) × 答题次数
```

含义：
- 掌握率越低 → 权重越高 → 越容易被选中出题
- 答题次数越多（说明多次练习仍未掌握） → 权重越高

### 举例
| 知识点 | 掌握率 | 答题次数 | 权重 |
|--------|--------|---------|------|
| 注意力机制 | 30% | 5 | (1-0.3)×5 = 3.5 |
| 反向传播 | 80% | 4 | (1-0.8)×4 = 0.8 |
| 损失函数 | 50% | 3 | (1-0.5)×3 = 1.5 |

「注意力机制」被选中的概率最高（3.5 / 5.8 ≈ 60%）。

## Q6：答错题后系统会做什么？

**A：** 触发**错题追问**机制：

```
用户答错
    │
    ├─ 显示正确答案和解析
    │
    ├─ 更新知识追踪（该知识点的掌握率下降）
    │
    └─ LLM 生成针对性追问题
         └─ 追问题聚焦于用户错误的原因
         └─ 存入 QuizAttempt 的 followup_question 字段
```

### 追问题的设计意图
不只是告诉用户「答案是 C」，而是：
- 分析用户为什么选错（常见误区）
- 生成一道相关但不同角度的题目
- 确认用户是否真正理解了

---

## Q7：错题本是如何工作的？

**A：** 错题本从 QuizAttempt 表中获取 `is_correct = False` 的记录，提供：

1. **错题列表**：按知识点分组，显示错误率最高的 Top N
2. **重做功能**：用户可以重新作答错题
3. **追问题**：如果之前生成了追问题，可以继续练习

设计上错题本和知识追踪是联动的——重做错题并答对后，该知识点的掌握率会上升，薄弱标记可能被移除。

## Q8：苏格拉底对话是什么？为什么要加这个功能？

**A：**

### 什么是苏格拉底教学法
苏格拉底教学法是一种**通过提问来引导学习**的方法——老师不直接给答案，而是通过一系列精心设计的问题，引导学生自己发现答案。

### 为什么要加
传统的问答系统是「你问我答」，学生被动接收知识。研究表明，**主动思考比被动接收**的学习效果好得多。苏格拉底对话让系统从「知识传递者」变成「思考引导者」。

### 与普通问答的核心区别
| 普通问答 | 苏格拉底对话 |
|---------|-------------|
| 用户问：什么是 Transformer？ | 用户说：我想了解 Transformer |
| 系统答：Transformer 是... | 系统问：你知道传统 RNN 在处理长序列时有什么问题吗？ |
| 学生被动接收 | 学生主动思考 |

## Q9：苏格拉底对话有哪些阶段？是如何推进的？

**A：** 对话分四个阶段，逐步深入：

```
阶段 1: 探索（Exploration）
  └─ 了解学生已有知识，找到切入点
  └─ 「你对 X 概念了解多少？」

阶段 2: 澄清（Clarification）
  └─ 帮助厘清模糊概念
  └─ 「你说的 Y 具体指什么？能举个例子吗？」

阶段 3: 深入（Deepening）
  └─ 引导深层思考
  └─ 「如果 Z 条件改变，结果会怎样？」

阶段 4: 综合（Synthesis）
  └─ 帮助形成完整理解
  └─ 「你能用自己的话总结一下 X 的核心思想吗？」
```

### 阶段推进的判断依据
LLM 根据对话进展返回结构化数据：
- `phase`：当前阶段
- `progress`：进度百分比
- `question`：下一个引导问题
- `encouragement`：鼓励语
- `hint`：如果学生卡住，给一个小提示

## Q10：苏格拉底引擎如何获取相关知识来辅助提问？

**A：** 苏格拉底引擎也依赖**检索系统**：

```
学生输入话题/回答
    │
    ├─ 从话题中提取关键词
    │
    ├─ 用 HybridRetriever 检索相关文本块
    │
    └─ 将文本块作为隐含知识，辅助 LLM 设计引导问题
```

关键点：**学生看不到检索到的内容**。这些内容只是帮助 LLM 了解正确知识，从而设计出有针对性的引导问题。

如果学生的回答偏离了正确方向，LLM 可以根据检索到的正确知识来纠偏引导。

---

## Q11：苏格拉底对话结束后会生成什么？

**A：** 当对话轮次足够多（≥ 4 轮）时，用户可以请求生成**对话总结**：

总结包括：
- 讨论了哪些核心概念
- 学生在哪些点上有很好的理解
- 哪些地方还需要进一步学习
- 建议的下一步学习方向

这个总结帮助学生回顾整个对话的收获，也可以作为后续学习的指引。

---

## Q12：三个学习子模块如何协同工作？

**A：** 它们形成一个**多维度学习闭环**：

```
               上传资料
                  │
    ┌─────────────┼─────────────┐
    ▼             ▼             ▼
 智能问答     测验练习      苏格拉底
（查资料）   （练习检验）   （深入思考）
    │             │             │
    └──────┬──────┘             │
           ▼                   │
      知识追踪 ←───────────────┘
           │
           ▼
      薄弱点识别
           │
     ┌─────┼─────┐
     ▼           ▼
  专项测验   推荐学习
（针对薄弱） （给建议）
```

三个入口、一个追踪中心、形成闭环。
